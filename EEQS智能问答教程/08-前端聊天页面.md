# 08 · 前端聊天页面

> 目标：在 EEQS 现有前端里新增智能问答页——流式打字机效果、Markdown/表格/图表渲染、写操作确认卡片。
> 以 Vue 3 为主线示例（React 思路一致，差异在 §6 说明）。

---

## 1. 页面结构

```
ChatView.vue
├── SessionList.vue      会话列表（新建/切换/删除，session_id 对应后端 thread_id）
├── MessageList.vue      消息流
│   ├── UserBubble.vue       用户气泡
│   ├── AiBubble.vue         AI 气泡：Markdown + 打字机光标
│   ├── DataTable.vue        查询结果表格（工具返回的结构化数据）
│   ├── ChartImage.vue       预测图（base64 / ECharts 折线）
│   └── ConfirmCard.vue      ⭐ 写操作确认卡片（HITL UI）
└── ChatInput.vue        输入框（Enter 发送 / Shift+Enter 换行 / 发送中断流）
```

## 2. 核心：用 fetch 接收 SSE（能带 JWT header）

浏览器原生 `EventSource` 不支持自定义请求头，用 `fetch` + 流读取（推荐直接装 `@microsoft/fetch-event-source`）：

```bash
npm i @microsoft/fetch-event-source marked dompurify highlight.js
```

```ts
// src/api/chat.ts
import { fetchEventSource } from '@microsoft/fetch-event-source'

export interface ChatHandlers {
  onToken: (t: string) => void
  onConfirmRequest: (payload: { action: string; summary: string }) => void
  onDone: () => void
  onError: (e: unknown) => void
}

export function streamChat(
  sessionId: string, message: string, h: ChatHandlers, signal: AbortSignal,
) {
  return fetchEventSource('/ai-api/chat', {
    method: 'POST',
    signal,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${localStorage.getItem('eeqs_token')}`,  // 复用平台登录态
    },
    body: JSON.stringify({ session_id: sessionId, message }),
    onmessage(ev) {
      const msg = JSON.parse(ev.data)
      if (msg.type === 'token') h.onToken(msg.data)
      else if (msg.type === 'confirm_required') h.onConfirmRequest(msg.data)
      else if (msg.type === 'done') h.onDone()
    },
    onerror: h.onError,
  })
}
```

> 后端配合：`interrupt` 触发时，FastAPI 端点先把 `{"type":"confirm_required", ...}` 作为一条 SSE 事件推给前端再挂起（03 篇 event_stream 里捕获中断事件即可）。

## 3. AI 气泡：打字机 + Markdown 安全渲染

```vue
<!-- AiBubble.vue -->
<script setup lang="ts">
import { computed } from 'vue'
import { marked } from 'marked'
import DOMPurify from 'dompurify'   // ⭐ 必须：防 LLM 输出 XSS（OWASP LLM05）

const props = defineProps<{ content: string; streaming: boolean }>()
const html = computed(() =>
  DOMPurify.sanitize(marked.parse(props.content) as string))
</script>

<template>
  <div class="ai-bubble">
    <div class="markdown-body" v-html="html" />
    <span v-if="streaming" class="cursor">▍</span>
  </div>
</template>
```

> ⚠️ 安全红线：**绝不允许**把 LLM 输出直接 `v-html` 而不经过 DOMPurify——模型输出可能含 `<script>`（无论来自注入还是巧合），这是 OWASP LLM05 在前端的落点。

## 4. 确认卡片（HITL 的另一半）

```vue
<!-- ConfirmCard.vue -->
<template>
  <div class="confirm-card">
    <p>⚠️ 智能体请求执行写操作：</p>
    <p class="summary">{{ payload.summary }}</p>
    <button @click="respond(true)"  :disabled="answered">✅ 确认执行</button>
    <button @click="respond(false)" :disabled="answered">❌ 取消</button>
  </div>
</template>

<script setup lang="ts">
import { ref } from 'vue'
import axios from 'axios'
const props = defineProps<{ sessionId: string; payload: any }>()
const answered = ref(false)
async function respond(confirm: boolean) {
  answered.value = true
  await axios.post('/ai-api/chat/confirm',
    { session_id: props.sessionId, confirm },
    { headers: { Authorization: `Bearer ${localStorage.getItem('eeqs_token')}` } })
  // 后端恢复执行后，结果可通过轮询或新的 SSE 事件推回
}
</script>
```

体验细节：确认卡片超时 5 分钟未操作视为取消；操作后卡片置灰留痕（审计可见性）。

## 5. 状态管理要点（Pinia）

```ts
// stores/chat.ts 关键状态
{
  sessions: Session[]            // 会话列表（持久化到后端或 localStorage）
  currentSessionId: string
  messages: Record<string, Message[]>   // session_id -> 消息
  streaming: boolean             // 流式中禁止重复发送
  abortController: AbortController | null  // 支持"停止生成"
}
```

- **停止生成**：`abortController.abort()` 断开 fetch，后端检测到连接关闭应取消 LLM 调用（省钱）。
- **历史恢复**：刷新页面后用 `session_id` 拉取历史消息（后端从 checkpointer 或消息表读）。
- **结构化数据与文本分离**：工具的表格/图表数据走独立 SSE 事件（`type: "table"` / `"chart"`），不要混在 token 流里让前端猜。

## 6. React 差异速记

| Vue | React |
|---|---|
| `computed` | `useMemo` |
| Pinia store | Zustand / Redux |
| `v-html` + DOMPurify | `dangerouslySetInnerHTML` + DOMPurify（同样必须消毒） |
| fetchEventSource 用法 | 完全相同 |

若时间紧，也可直接集成开源聊天 UI 组件库（如 Ant Design X、chatui）再改样式贴合 EEQS 主题。

## 7. 体验加分项

- 输入框上方放 3~4 个**示例问题**（"查 A 站上月 COD 均值"/"预测未来 7 天趋势"），降低用户学习成本，也间接约束提问分布。
- AI 回答下方放 👍👎 反馈按钮，数据回流到评估体系（09 篇）。
- 回答中的"来源：《XX手册》"渲染成可展开的引用卡片。
- 加载状态分阶段提示："正在检索知识库… → 正在生成 SQL… → 正在执行查询…"（把工具调用事件也推成 SSE），等待感大幅降低。
