# 07 · 预测数据分析

> 目标：让用户说"预测一下 A 站点未来 7 天的 COD 趋势"，智能体能取数 → 建模 → 出图 → 用自然语言解读并**明确不确定性**。
> 核心认知：**模型（LLM）不做预测计算**，它只做意图理解、参数解析和结果解读；预测由确定性代码完成。

---

## 1. 职责边界（先立规矩）

```
LLM 负责：理解"哪个站点、哪个指标、预测多久" → 调工具 → 解读结果
代码负责：取历史数据 → 清洗 → 时序建模 → 生成预测值+置信区间 → 画图
```
永远不要让 LLM 自己"心算"预测数字——那是幻觉的重灾区。

## 2. 预测方法选型（由简到繁）

| 层级 | 方法 | 适用 | 依赖 |
|---|---|---|---|
| L1 | 移动平均 / 指数平滑（Holt-Winters） | 有季节性的平稳序列，数据 < 几千点 | statsmodels |
| L2 | Prophet | 有明显日/周/年周期 + 节假日效应，缺测值多 | prophet |
| L3 | LightGBM + 滞后特征 | 多变量（温度、流量等协变量）、非线性 | lightgbm |
| L4 | 深度时序（Transformer 类） | 数据量极大且前面都不够用 | 先别考虑 |

**建议从 L1 起步**：EEQS 监测类数据多为日/小时级单指标序列，Holt-Winters 或 Prophet 足够 demo 和初期生产。把接口设计好，以后换模型不动上层。

## 3. 预测工具实现

```python
# app/tools/predict_tool.py
import io, base64
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from statsmodels.tsa.holtwinters import ExponentialSmoothing
from langchain_core.tools import tool

from app.db.loader import load_series   # 从业务库取数（走只读账号）

plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei"]  # 中文图例
plt.rcParams["axes.unicode_minus"] = False

def _forecast(series: pd.Series, periods: int, seasonal: int = 7):
    """Holt-Winters 加法季节模型 + 简单残差置信区间"""
    model = ExponentialSmoothing(
        series, trend="add", seasonal="add", seasonal_periods=seasonal
    ).fit(optimized=True)
    fc = model.forecast(periods)
    resid_std = (model.resid.std() if hasattr(model, "resid")
                 else (series - model.fittedvalues).std())
    upper = fc + 1.96 * resid_std      # 近似 95% 区间
    lower = fc - 1.96 * resid_std
    return fc, lower, upper

def _plot(history: pd.Series, fc, lower, upper) -> str:
    fig, ax = plt.subplots(figsize=(8, 4))
    history.tail(60).plot(ax=ax, label="历史值")
    fc.plot(ax=ax, label="预测值", color="orange")
    ax.fill_between(fc.index, lower, upper, color="orange", alpha=0.2, label="95% 置信区间")
    ax.legend(); ax.grid(alpha=0.3)
    buf = io.BytesIO()
    fig.savefig(buf, format="png", dpi=110, bbox_inches="tight")
    plt.close(fig)
    return base64.b64encode(buf.getvalue()).decode()

@tool
def forecast_indicator(station_id: str, indicator: str, days: int = 7) -> dict:
    """预测某站点某监测指标未来 N 天的趋势（默认 7 天，上限 30 天）。
    输入：station_id 站点编号；indicator 指标代码（如 COD）；days 预测天数。
    返回：预测摘要、逐日预测值和置信区间、趋势图（base64）。"""
    days = min(days, 30)                                   # 防滥用（LLM10）
    series = load_series(station_id, indicator, lookback_days=180)
    if len(series) < 30:
        return {"error": "历史数据不足 30 个点，无法给出可靠预测，建议先查询历史数据。"}

    fc, lower, upper = _forecast(series, days)
    img_b64 = _plot(series, fc, lower, upper)

    return {
        "summary": {
            "station": station_id, "indicator": indicator,
            "trend": "上升" if fc.iloc[-1] > fc.iloc[0] else "下降或持平",
            "avg_forecast": round(float(fc.mean()), 2),
        },
        "daily": [{"date": str(d.date()), "value": round(float(v), 2),
                   "lower": round(float(l), 2), "upper": round(float(u), 2)}
                  for d, v, l, u in zip(fc.index, fc, lower, upper)],
        "chart_base64": img_b64,
        "disclaimer": "基于近 180 天数据的统计外推，未考虑突发工况，仅供参考。",
    }
```

## 4. LLM 解读规范（system prompt 片段）

```
- 调用 forecast_indicator 后，解读必须包含：
  ① 趋势方向与幅度（用返回的数字，不要自己编）；
  ② 置信区间的含义（"未来值有约 95% 概率落在区间内"）；
  ③ 逐字附上 disclaimer 内容；
  ④ 历史数据不足或返回 error 时，如实告知并给出替代建议（如改为查询历史趋势）。
```

前端拿到 `chart_base64` 直接渲染图片，`daily` 数组可同时渲染成表格/折线图（08 篇）。

## 5. 工程细节

1. **数据质量前置检查**：`load_series` 里做缺测值统计、异常值（3σ）标记；缺测 >30% 直接拒绝预测并说明——**垃圾进垃圾出是预测功能最大的信任杀手**。
2. **缓存**：同站点同指标同天数的预测结果缓存 1~6 小时（Redis），避免重复计算 + 重复出图。
3. **超时与资源**：预测计算放线程池（`run_in_executor`），单次超时 30s；`days` 上限 30。
4. **效果度量**：用"时间切片回测"——用前 N-14 天建模，预测后 14 天与真实值算 MAPE，写进运维报表。MAPE 持续恶化说明该换方法或加协变量了。
5. **升级路径**：当业务方开始问"考虑降雨量的影响"时，就是上 LightGBM + 协变量的信号；接口不变，只换 `_forecast` 内部实现。

## 6. 合规与表达红线

- 预测结果页/回答里**必须**带不确定性说明（上面的 disclaimer），这在环保、监测类业务里既是技术诚实也是责任边界。
- 避免"将会超标"这种断言，用"预测区间上限接近限值，建议关注"这类表达。
