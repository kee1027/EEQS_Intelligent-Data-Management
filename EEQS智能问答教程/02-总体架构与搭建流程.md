### 三条设计红线
1. **AI 服务直连业务库只用只读账号**——即使注入完全成功，攻击者拿到的也只是 SELECT。
2. **一切写操作（增删改）不走 SQL，走 EEQS 主后端的既有 API**——主后端的参数校验、事务、审计全部复用，AI 服务只负责"理解意图+组装参数+要确认"。
3. **权限判断发生在工具执行前的代码里**，不在提示词里。

## 2. 模块拆分与职责

| 模块 | 文件位置（建议） | 职责 |
|---|---|---|
| API 层 | `app/api/chat.py` | SSE 端点、请求/响应模型 |
| 中间件 | `app/middleware/` | 鉴权、限流、注入检测、审计 |
| Agent 层 | `app/agent/graph.py` | system prompt、工具注册、记忆 |
| 工具层 | `app/tools/` | `sql_tool.py` / `rag_tool.py` / `predict_tool.py` / `crud_tool.py` |
| 安全层 | `app/security/` | sqlglot 校验器、RBAC 策略、注入分类器 |
| 数据层 | `app/db/` | 只读连接、向量库连接、schema 元数据 |
| 配置 | `app/core/config.py` | pydantic-settings 读 `.env` |

## 3. 一次请求的完整链路（以"查 A 站点上月数据"为例）

```
1. 前端 POST /api/chat  {message, session_id}   (携带 JWT)
2. 中间件: 验证 JWT → 拿到 user_id, roles
3. 中间件: 注入检测器打分 → 高危则直接拒绝并写审计日志
4. Agent 拿到消息 + 历史（checkpoint 按 session_id 恢复）
5. 模型决策: 调用 query_database 工具
6. 工具内:
   a. RAG 检索相关表 schema（表太多时的关键优化）
   b. 模型生成 SQL
   c. sqlglot AST 校验: 必须单条 SELECT、表白名单、自动补 LIMIT
   d. RBAC: 该 role 能不能看这张表？行级过滤条件注入 WHERE
   e. 只读账号执行，超时 10s，截断 50 行
7. 工具结果回给模型 → 模型生成自然语言总结
8. SSE 逐 token 推回前端，同时结构化数据（表格 JSON）走另一条 SSE 事件
9. 全链路写审计日志：谁、问了什么、生成了什么 SQL、查了哪些表、耗时、token 数
```

## 4. 搭建流程总览（每步对应一篇详细教程）

```
Step 0  环境准备          Python 3.11+ / uv / Docker        → 03 篇 §1
Step 1  最小问答骨架      FastAPI + create_agent + SSE       → 03 篇 §2-§4
Step 2  接入平台登录态     JWT 校验中间件                     → 03 篇 §5
Step 3  数据查询能力       Text2SQL 工具 + sqlglot 只读校验   → 04 篇 §1-§4
Step 4  权限体系          RBAC + 行级权限 + 只读账号          → 04 篇 §5
Step 5  RAG 知识库        文档入库 + 混合检索 + 引用回答       → 06 篇
Step 6  预测分析          预测工具 + 图表返回                 → 07 篇
Step 7  写操作闭环        增删改工具 + interrupt 二次确认      → 03 篇 §6 + 04 篇 §6
Step 8  注入防范加固       检测器 + Spotlighting + 对抗测试    → 05 篇
Step 9  前端页面          聊天 UI + SSE + 确认卡片            → 08 篇
Step 10 工程化上线        日志/评估/测试/Docker/监控          → 09 篇
```

> **顺序的讲究**：先查（只读、风险低）后写（增删改、风险高）；先本地后上线；每一步都可独立演示。

## 5. 关键决策记录（ADR 速览）

写进你的项目文档，答辩/交接时非常加分：

| 决策 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|
| AI 能力放哪 | 独立 Python 微服务 | LangChain 生态在 Python；与主后端解耦 | 主后端内嵌（Java 生态弱） |
| Agent 框架 | LangChain 1.0 `create_agent` | 官方主线、生态最大 | Dify（定制受限）、自研循环（重复造轮） |
| 查询安全 | sqlglot AST 校验 + 只读账号双层 | 单靠正则拦不住注入 | 纯 prompt 约束（无效） |
| 写操作 | 走主后端 API + HITL 确认 | 复用校验与审计；误操作可拦 | 直连库执行 DML（高危） |
| 向量库 | pgvector | 业务库已用 PG 则零新增运维 | Milvus（小数据量杀鸡用牛刀） |
