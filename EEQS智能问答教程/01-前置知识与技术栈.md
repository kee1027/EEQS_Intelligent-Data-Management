## 1. LLM 应用开发的 8 个核心概念

### 1.1 Token 与上下文窗口（Context Window）
- 模型按 **token** 计费和处理，中文大约 1 个汉字 ≈ 1~2 token。
- 上下文窗口是模型一次能"看到"的总长度（如 128K token）。你的 system prompt + 历史对话 + RAG 检索内容 + 工具返回，全部挤在这个窗口里。
- **工程含义**：上下文不是免费的，要做历史压缩、工具返回截断（见 09 篇成本控制）。

### 1.2 Prompt 的角色分层
```
system（开发者指令，最高优先级）
user（用户输入，不可信）
assistant（模型回复）
tool（工具返回结果，同样不可信！）
```
理解"指令与数据走同一个通道"是理解 Prompt 注入的钥匙（05 篇展开）。

### 1.3 Function Calling / Tool Use（本项目基石）
你给模型一组"工具"（带名称、描述、参数 JSON Schema 的函数），模型不直接执行，而是**输出结构化请求**："请调用 `query_database`，参数是 `{sql: '...'}`"。你的代码真正执行后，把结果塞回对话，模型再组织语言回答。

```python
from langchain_core.tools import tool

@tool
def query_database(sql: str) -> str:
    """对 EEQS 业务库执行只读 SQL 查询，返回前 50 行。输入必须是合法 SELECT 语句。"""
    ...
```
> 工具的 docstring 就是给模型看的"说明书"，写得好坏直接决定调用准确率。

### 1.4 Agent 与 ReAct 循环
Agent = LLM + 工具 + 循环。循环逻辑（ReAct 模式）：
```
用户问题 → 模型思考(Thought) → 决定调工具(Action) → 执行得到结果(Observation)
        → 模型再看结果 → 继续调工具 or 输出最终答案
```
**2026 年的现状**：LangChain 1.0 用 `create_agent` 一行封装了这个循环；旧的 `AgentExecutor` 已弃用（2026-12 停止维护），网上 2024 年之前的教程大量使用它，**不要抄**。

### 1.5 LangChain vs LangGraph（2026 版结论）
| | LangChain 1.x | LangGraph 1.x |
|---|---|---|
| 定位 | 组件库 + 高层 Agent API | 状态机/图编排引擎 |
| 适合 | 标准 Agent 循环、RAG 链 | 多步骤、多分支、循环、人工介入（HITL）、可恢复的长流程 |
| 关系 | `create_agent` 底层就是 LangGraph | — |

**本项目策略**：主干用 `create_agent`；在需要"写操作二次确认"处用 LangGraph 的 `interrupt` + checkpointer（断点续跑）。这正是官方推荐的渐进式路径。

### 1.6 RAG（检索增强生成）
```
离线：文档 → 切块(chunk) → Embedding 向量化 → 存入向量库
在线：用户问题 → 向量化 → 向量库检索 top-k → 塞进 prompt → LLM 生成带依据的回答
```
模型本身没有被训练/修改，变的只是 prompt 里的上下文——这是 RAG 便宜、可热更新的根本原因。细节见 06 篇。

### 1.7 Text2SQL
让模型把自然语言翻译成 SQL。生产级要点：**schema 检索**（表太多塞不下，用 RAG 选相关表）、few-shot 示例、**AST 级只读校验**、行列限制。细节见 04 篇。

### 1.8 SSE（Server-Sent Events）
HTTP 长连接流式推送，前端逐字显示回答（"打字机效果"）。比 WebSocket 简单、够用于"服务端→客户端"单向流。前后端代码见 03/08 篇。

## 2. 关键第三方库速查

| 库 | 干什么 | 一句话上手 |
|---|---|---|
| `langchain` | Agent/链/模型抽象 | `create_agent(model, tools=[...])` |
| `langgraph` | 图编排、断点续跑、HITL | `StateGraph` + `interrupt()` |
| `langchain-core` | tool、message、prompt 基类 | `@tool` 装饰器 |
| `fastapi` | AI 服务 HTTP 框架 | `@app.post("/chat")` |
| `uvicorn` | ASGI 服务器 | `uvicorn main:app --reload` |
| `sqlglot` | SQL 解析/校验/改写 | AST 白名单校验只读 |
| `psycopg` / `pymysql` / `sqlalchemy` | 数据库连接 | 用**只读账号** |
| `pgvector` | Postgres 向量扩展 | `CREATE EXTENSION vector;` |
| `sentence-transformers` / `FlagEmbedding` | 本地跑 BGE-M3 embedding | 两行出向量 |
| `statsmodels` / `prophet` | 时序预测 | 07 篇 |
| `pydantic` | 数据校验（贯穿全项目） | 请求/响应/工具参数全用它 |

## 3. 模型怎么选（国内落地视角）

| 场景 | 建议 |
|---|---|
| 开发调试 | Ollama 本地跑 Qwen2.5:7b/14b，零成本随便造 |
| 生产主模型 | DeepSeek-V3.x / 通义千问 Max / GLM 等，工具调用能力强、价格低 |
| Embedding | BGE-M3（本地）或厂商 API |
| Rerank（可选增强） | bge-reranker-v2-m3 |

**统一抽象**：用 `init_chat_model("deepseek:...")` 这类写法，换模型只改配置不改代码（03 篇有示例）。

## 4. 必须建立的两个"安全直觉"

1. **所有进入上下文的内容都不可信**：用户输入、RAG 检索回来的文档、数据库里存的文本、工具返回值——都可能藏着注入指令。
2. **权限必须在代码层强制，不能靠提示词哀求**："请不要执行删除"没用；只读数据库账号 + AST 校验 + RBAC 中间件才有用。

## 5. 课程与资料推荐（精选，按优先级）

### 免费 / 首选
1. **LangChain Academy（官方免费）** — academy.langchain.com
   跟着 1.0 版课程走，直接学 `create_agent`、middleware、LangGraph 持久化。**这是本项目的官方对标课程，优先级最高。**
2. **DeepLearning.AI 短课（吴恩达系列，免费旁听）**
   - *LangChain for LLM Application Development* — 入门概念（注意：用的是旧版 API，看思想不看代码）
   - *LangChain: Chat with Your Data* — RAG 全流程：加载→切分→向量库→检索，对应 06 篇
   - *Agentic AI*（2025）— 吴恩达讲 Agent 设计模式（反思、工具、规划、多智能体），一天可刷完
   - *Quality and Safety of LLM Applications* — 对应 05 篇
   - B 站搜"吴恩达 LangChain"有全套中文字幕搬运。
3. **官方文档（2025 起已统一）**：docs.langchain.com — Python/JS 示例并排，查 API 以它为准。
4. **OWASP Top 10 for LLM Applications 2025**（genai.owasp.org）— 安全篇的事实标准，05 篇是它的落地版。

### 中文实践向
5. 极客时间 / B 站的 LangChain 实战课（选 2025 年后更新、讲 `create_agent`/LangGraph 的版本；讲 `AgentExecutor` 的老课直接跳过代码部分）。
6. 若主后端是 Java：**LangChain4j** 官方文档 + 相关中文课（B 站"LangChain4j"），但本教程仍建议 AI 服务用 Python。

### 书籍（进阶）
7. 《Building LLMs for Production》/ O'Reilly《LLM Engineer's Handbook》— RAG 评估、微调、部署体系化。
8. 论文/博客：Simon Willison 的 prompt injection 系列博客（05 篇引用了他的 Dual-LLM 思想）。

### 学习顺序建议
```
Day 1-2: LangChain Academy quickstart 跑通
Day 3-5: Chat with Your Data（RAG 课）+ 本教程 06 篇同步实践
第 2 周起: Agentic AI + OWASP LLM Top 10 通读
```
