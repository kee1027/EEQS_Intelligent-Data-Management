# 09 · 工程实践与部署

> 目标：把"能跑"变成"能上线、能运维、能迭代"。本篇也是终端命令的汇总篇。

---

## 1. 配置与密钥管理

- 所有密钥（模型 API Key、数据库密码、JWT 密钥）只走环境变量 / `.env`，**`.env` 进 `.gitignore`**，仓库里放 `.env.example` 模板。
- 系统提示词里不放任何秘密（05 篇原则）。
- 配置用 `pydantic-settings` 集中管理（03 篇 §1），禁止散落各处的 `os.environ.get`。

## 2. 日志与可观测

**最小方案**（自建审计表）：
```sql
CREATE TABLE ai_audit_log (
    id bigserial PRIMARY KEY,
    ts timestamptz DEFAULT now(),
    user_id varchar, session_id varchar,
    question text, generated_sql text, tools_called jsonb,
    guard_score numeric, tokens_in int, tokens_out int,
    latency_ms int, status varchar, error text
);
CREATE INDEX ON ai_audit_log (user_id, ts);
```

**推荐方案**（LangSmith / 开源 Langfuse）：
```bash
# .env 加三行即完成全链路 trace（每次模型调用、工具调用、token 用量自动记录）
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=ls__xxx
LANGSMITH_PROJECT=eeqs-ai
```
排查"为什么这个问题答得烂"时，trace 能直接看到：检索到了什么、生成了什么 SQL、模型哪一步想歪了。**没有 trace 的 Agent 项目等于没有仪表盘的飞机。**

## 3. 测试体系（四层）

| 层 | 内容 | 命令 |
|---|---|---|
| 单元测试 | sqlglot 校验、RBAC、注入检测器 | `uv run pytest tests/ -v` |
| 集成测试 | 起测试库，跑 `/api/chat` 全链路 | `uv run pytest tests/integration -v` |
| 离线评估 | Text2SQL 准确率、RAGAS、注入拦截率 | `uv run python -m app.eval.xxx` |
| 对抗测试 | 注入测试集（05 篇 §7）进 CI，回归必跑 | 同上 |

CI（GitHub Actions 示例要点）：PR 触发 ①②；每晚定时 ③④，指标低于基线则报警。

## 4. 成本与限流（OWASP LLM10）

```python
# 用户级限流（slowapi）
from slowapi import Limiter
limiter = Limiter(key_func=lambda req: get_user_id(req))
@limiter.limit("20/minute")        # 每用户每分钟 20 条
async def chat(...): ...
```
- 单次请求 token 预算：历史对话超 8K token 就摘要压缩（LangChain `SummarizationMiddleware` 或自写）。
- 工具返回统一截断（查询 50 行、检索 8 段），上下文成本立省一半以上。
- 每周看一次 LangSmith 成本看板，找出"最贵的问题类型"定向优化。

## 5. Docker 化与部署

```dockerfile
# Dockerfile
FROM python:3.11-slim
RUN pip install uv
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev
COPY app ./app
EXPOSE 8000
CMD ["uv", "run", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--workers", "2"]
```

```yaml
# docker-compose.yml（与 EEQS 主系统并排部署）
services:
  eeqs-ai:
    build: .
    env_file: .env
    ports: ["8001:8000"]
    restart: unless-stopped
    depends_on: [db]
  # db / redis 复用平台现有实例即可
```

Nginx 关键点（SSE 必须）：
```nginx
location /ai-api/ {
    proxy_pass http://eeqs-ai:8000/api/;
    proxy_buffering off;            # ⭐ 关缓冲，否则流式变整段
    proxy_read_timeout 300s;
    add_header X-Accel-Buffering no;
}
```

## 7. 常用终端命令速查

```bash
# 开发
uv add <pkg>                          # 加依赖
uv run uvicorn app.main:app --reload  # 起服务
uv run pytest -v                      # 跑测试
uv run ruff check --fix               # 代码检查

# 数据库
psql $DATABASE_URL -c "\d monitoring_data"      # 看表结构
psql $DATABASE_URL -c "SELECT * FROM ai_audit_log ORDER BY ts DESC LIMIT 20;"

# 向量库
psql $DATABASE_URL -c "SELECT count(*) FROM kb_chunks;"

# 部署
docker compose up -d --build          # 构建并后台启动
docker compose logs -f eeqs-ai        # 跟日志
docker compose exec eeqs-ai bash      # 进容器排查

# 模型（Ollama 本地调试）
ollama pull qwen2.5:14b
ollama list && ollama ps

# 压测接口（简单版）
seq 50 | xargs -P 10 -I{} curl -s -o /dev/null -w "%{http_code}\n" \
  -X POST http://localhost:8000/api/chat -H "Authorization: Bearer $T" \
  -H "Content-Type: application/json" -d '{"session_id":"p{}","message":"你好"}'
```

## 8. 迭代节奏建议

上线后按"周"迭代：每周看审计日志里**答得差的 top10 问题**和 👎 反馈 → 归类（schema 不熟？检索不到？prompt 歧义？）→ 修一类问题 → 跑评测集确认无回归 → 发布。这个"badcase 驱动"循环比任何架构调整都更能提升用户感知质量。
