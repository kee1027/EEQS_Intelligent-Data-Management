# 手动写代码时的 Git 日常操作指南（不经过 AI）

> 适用场景：你自己在任意一台设备上写代码，不让我代劳 Git 操作时的完整流程。
> 只需记住一个节奏：**开工 pull → 写代码 → 提交 → 收工 push**。

---

## 一、每天的标准流程

**① 开工（打开项目第一件事）**

```bash
cd 项目目录        # 例：cd /d/projects/rag-tutorials
git pull           # 拉取另一台设备（或之前）推送的最新代码
```

**② 写代码**：用 VS Code / 任意编辑器正常改文件。

**③ 提交（一天可多次，做完一件小事就提交一次）**

```bash
git status                          # 看看改了哪些文件（好习惯）
git add .                           # 暂存所有改动
git commit -m "一句话说明改了什么"   # 例如：git commit -m "修复导出乱码问题"
```

**④ 收工（关闭电脑前最后一件事）**

```bash
git push
```

> 就这四步。记住：**push 了，另一台设备才能拿到；不 push，改动只存在这台电脑上。**

## 二、高频命令速查

| 我想…… | 命令 |
|--------|------|
| 看当前状态（改了哪些文件） | `git status` |
| 看具体改了哪些行 | `git diff` |
| 看提交历史 | `git log --oneline` |
| 撤销某个文件还没提交的修改 | `git checkout -- 文件名` |
| 改上一次提交的说明（还没 push 时） | `git commit --amend -m "新说明"` |
| 工作写一半要换设备 | `git add . && git commit -m "WIP" && git push`，另一台 pull 后继续 |

---

## 三、遇到报错怎么办

**`git push` 报 `non-fast-forward` / `rejected`**
→ 另一台设备推过新代码，你本地落后了。执行：

```bash
git pull
```

- 若自动合并成功 → 再 `git push` 即可。
- 若提示 **CONFLICT（冲突）** → 打开报错的文件，找到这样的标记：

```
<<<<<<< HEAD
你本机的代码
=======
远程拉下来的代码
>>>>>>> origin/main
```

手动保留想要的内容、**删掉三行标记**，保存后：

```bash
git add .
git commit -m "解决冲突"
git push
```

**`git push` 报 `Permission denied (publickey)`**
→ 这台设备的公钥没加到 GitHub。回到《06-设备B打通清单》第 3–4 步。

**连接 github.com 超时**
→ 网络问题，过一会儿重试，或切换网络。

**`git status` 显示一堆没动过的文件"被修改"**
→ 换行符配置问题，执行一次：

```bash
git config --global core.autocrlf true    # Windows
# macOS/Linux 用：git config --global core.autocrlf input
```

## 四、三条铁律（避免 90% 的麻烦）

1. **开工必 pull，收工必 push** —— 双设备不冲突就靠它。
2. **密钥、密码、`.env` 文件永不提交** —— 写进 `.gitignore`。
3. **已 push 的提交不要改写历史**（不用 `reset`/`amend`）—— 否则另一台设备会乱。

## 五、VS Code 图形化替代方案（不想敲命令时）

VS Code 自带 Git 面板（左侧第三个图标"源代码管理"）：

- 改动文件会列出来，点 **+** = `git add`
- 上方输入框写说明，点 **✓ 提交** = `git commit`
- 左下角 **同步更改** 按钮 = `git pull` + `git push` 一键完成

命令行和图形界面可以混用，效果完全一样。
