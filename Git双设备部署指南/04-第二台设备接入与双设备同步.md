# 04 · 第二台设备接入与双设备同步

> 本章先在**设备 B** 上完成接入，然后建立两台设备长期使用的同步纪律。这是双设备场景的核心章节。

---

## 4.1 设备 B 接入（一次性）

前提：设备 B 已完成 01 章（装 Git、配身份）和 02 章（生成密钥、绑定 GitHub、`ssh -T` 验证通过）。

```bash
# 进入存放项目的目录
cd ~/projects          # 或 Windows: cd /d/projects

# 克隆同一个仓库（同一个 SSH 地址）
git clone git@github.com:<你的用户名>/my-project.git

cd my-project

# 确认能看到设备 A 推送的历史
git log --oneline
# 应看到"初始提交：添加 README"等提交记录
```

至此两台设备都持有同一份仓库。**不需要在设备之间直接传文件，一切通过 GitHub 中转。**

---

## 4.2 双设备黄金法则

> **开工第一件事 `git pull`，收工最后一件事 `git push`。**

```
设备 A 的一天：
  git pull        ← 开工：拉取设备 B 昨晚的提交
  ...写代码...
  git add .
  git commit -m "..."
  git push        ← 收工：推上去，设备 B 才能拿到

设备 B 的另一天：
  git pull        ← 开工：拉取设备 A 昨天的成果
  ...
```

只要遵守这条纪律，两台设备**永远不会冲突**。

建议养成肌肉记忆的完整收工命令链：

```bash
git status          # 确认没有遗漏未提交的文件
git add .
git commit -m "今天的改动说明"
git push
```

## 4.3 如果忘了 push / pull 怎么办（冲突处理）

**场景**：设备 A 改了 `app.py` 并 push 了；设备 B 没有先 pull，也改了 `app.py` 同一区域并 commit，push 时被拒绝：

```
! [rejected]  main -> main (non-fast-forward)
hint: Updates were rejected because the remote contains work that you do not have locally.
```

别慌，按以下步骤处理：

```bash
# 第 1 步：先把远程的改动拉下来
git pull
```

此时有两种结果：

**结果一：自动合并成功**（两台设备改的不是同一处）——直接 `git push`，结束。

**结果二：出现冲突（CONFLICT）**。打开冲突文件，会看到 Git 插入的标记：

```python
<<<<<<< HEAD
# 你本机（设备 B）的代码
=======
# 远程（设备 A 推送上来）的代码
>>>>>>> origin/main
```

手动编辑：决定保留哪一边（或融合两边），**删掉 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记**，保存后：

```bash
git add app.py
git commit -m "合并设备A与设备B对 app.py 的修改"
git push
```

> 记住：**冲突不是事故，只是 Git 让你做一次人工裁决。** 裁决完提交即可。

## 4.4 有未完成的工作要换设备？用"进行中提交"

在设备 A 上代码写到一半要去用设备 B？直接提交一个 WIP（work in progress）：

```bash
git add .
git commit -m "WIP: 登录功能写了一半"
git push
```

在设备 B 上 `git pull` 后继续写，完成后可以再正常 commit。个人仓库里 WIP 提交完全无害。

> 进阶技巧（可选）：事后想把 WIP 提交合并成一条干净的历史，用 `git reset --soft HEAD~1` 撤销最后一次提交但保留改动，再重新 commit。不影响远程的提交才安全这么干。

## 4.5 双设备同步常见问题速查

| 症状 | 原因 | 处理 |
|------|------|------|
| push 报 `Permission denied (publickey)` | 该设备公钥没绑定 GitHub | 回到 02 章 2.4/2.5 节 |
| push 报 `non-fast-forward` | 远程有本地没有的提交 | `git pull` 后再 push |
| pull 报 `Your local changes would be overwritten` | 本地有未提交改动且与远程冲突 | 先 `git add . && git commit -m "WIP"` 再 pull |
| 连接 github.com 超时 | 网络问题 | 重试；或切换网络；长期不稳定考虑 Gitee |
| `git status` 满屏文件都显示 modified 但内容没变 | 两台设备换行符配置不一致 | 检查 01 章 1.4 节 `core.autocrlf` 是否按平台设置 |
