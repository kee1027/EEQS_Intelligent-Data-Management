# Git 双设备部署与使用完整指南

> 适用场景：同一用户在 **两台常用设备** 上从零搭建 Git 生态（以 GitHub 为远程仓库），
> 从安装 Git、创建仓库开始，到进入正常的提交 / 修改 / 双设备同步工作流。
>
> 编写时间：2026-08-17。版本基线：Git 2.55.0（2026-08-11 发布，当前最新维护版）。

## 你将搭建出的整体架构

```
        ┌─────────────────┐
        │   GitHub 远程仓库  │  ← 唯一权威数据源（origin）
        │  (origin/main)   │
        └────────┬────────┘
                 │  SSH 加密通道（每台设备一把独立密钥）
        ┌────────┴────────┐
        │                 │
  ┌─────▼──────┐    ┌─────▼──────┐
  │  设备 A      │    │  设备 B      │
  │ 本地仓库      │    │ 本地仓库      │
  │ (clone)    │    │ (clone)    │
  └────────────┘    └────────────┘
```

核心原则一句话：**GitHub 远程仓库是两台设备之间的"中转站"，任何设备上的工作结束后 push，开始前 pull。**

## 前置知识（3 分钟版）

- **Git**：安装在你电脑上的版本控制工具，负责记录每一次代码改动（快照）。
- **GitHub**：托管 Git 仓库的网站，相当于"云端备份 + 多设备中转站"。（国内网络访问 GitHub 偶尔不稳定，备选方案见 02 章末尾。）
- **仓库（repository / repo）**：一个被 Git 管理的项目文件夹。
- **commit（提交）**：一次改动的快照，带一条说明文字。
- **push / pull**：把本地提交上传到 GitHub / 把 GitHub 上的新提交下载到本地。
- **SSH 密钥**：让设备免密码、安全地连接 GitHub 的"钥匙"，**每台设备各配一把**。

## 关键假设（请确认）

1. 两台设备均为**你本人使用**，无多人协作需求 → 指南以最简单可靠的"单分支 + 同步纪律"为主，分支工作流作为进阶内容放在 05 章。
2. 远程托管平台默认使用 **GitHub**。如果你更倾向国内平台（Gitee / GitCode），02 章的操作完全同构，替换域名即可。
3. 两台设备的操作系统组合未指定 → 01 章同时给出 Windows / macOS / Linux 三种安装方式，按实际情况对号入座。

## 总耗时预估

- 首次完整搭建（设备 A + 设备 B）：约 40–60 分钟
- 此后日常使用：每天只需记住三个动作 —— **开工 pull、完工 push、提交 commit**
