> 本章是进阶内容与日常参考。前四章已经足够支撑双设备日常使用了；本章让你用得更从容。

## 5.1 分支工作流（进阶，可选）

**什么时候需要分支**：当你要做一个较大改动（比如重构某个模块），希望 `main` 分支始终保持可用状态，改坏了也不影响主线。

**个人双设备场景的推荐模型 —— 功能分支流**：

```bash
# 1. 从 main 拉一个新分支做功能
git pull
git checkout -b feature/登录优化

# 2. 在新分支上正常 add / commit / push
git add .
git commit -m "重构登录表单校验"
git push -u origin feature/登录优化

# 3. 功能完成，切回 main 并合并
git checkout main
git pull
git merge feature/登录优化
git push

# 4. 删除已合并的分支（本地 + 远程）
git branch -d feature/登录优化
git push origin --delete feature/登录优化
```

**常用分支命令**：

```bash
git branch              # 列出本地分支（* 号是当前分支）
git branch -a           # 列出本地 + 远程分支
git checkout main       # 切换到 main
git checkout -b 新分支   # 新建并切换
git merge 分支名         # 把指定分支合并进当前分支
```

> 双设备注意：分支也是通过 push/pull 同步的。在设备 A 建的分支 push 后，设备 B 执行 `git pull` 再 `git checkout feature/登录优化` 就能接着做。

## 5.2 后悔药系列（撤销操作）

| 我想…… | 命令 | 说明 |
|--------|------|------|
| 撤销工作区某个文件的修改（还没 add） | `git checkout -- 文件名` | 文件恢复到上次提交的样子，**改动丢弃** |
| 把文件从暂存区拿出来（已 add 未 commit） | `git reset 文件名` | 改动还在工作区，只是取消暂存 |
| 修改上一次 commit 的说明文字 | `git commit --amend -m "新说明"` | 仅限**还没 push** 的提交 |
| 撤销上一次 commit 但保留改动 | `git reset --soft HEAD~1` | 仅限还没 push 的提交 |
| 回退到某个历史版本查看 | `git checkout <commit号>` | 看完全局后 `git checkout main` 回来 |
| 查看所有历史 | `git log --oneline --graph` | 简洁图形化历史 |

> 黄金安全线：**已经 push 到远程的提交，不要用 reset/amend 改写**。双设备场景下改写已推送的历史会让另一台设备陷入混乱。

## 5.3 命令速查表（按使用频率排序）

| 频率 | 命令 | 作用 |
|------|------|------|
| ⭐⭐⭐ | `git status` | 看当前状态，随时用 |
| ⭐⭐⭐ | `git pull` | 开工：拉取远程最新 |
| ⭐⭐⭐ | `git add .` | 暂存所有改动 |
| ⭐⭐⭐ | `git commit -m "说明"` | 提交快照 |
| ⭐⭐⭐ | `git push` | 收工：推送到远程 |
| ⭐⭐ | `git diff` | 查看未暂存的具体改动 |
| ⭐⭐ | `git log --oneline` | 查看提交历史 |
| ⭐⭐ | `git checkout -b 分支` | 新建并切换分支 |
| ⭐ | `git remote -v` | 查看远程仓库地址 |
| ⭐ | `git stash` / `git stash pop` | 临时收起未完成的改动 / 恢复 |
| ⭐ | `git clone <地址>` | 克隆仓库（每设备一次） |

## 5.4 避坑清单（血泪经验）

1. **永远不要提交密钥和密码**：`.env`、私钥、API Key 一律写进 `.gitignore`。一旦误提交并 push，即使删除文件，历史里仍存在——应立刻更换该密钥。
2. **不要把整个家目录或磁盘根目录初始化成仓库**：`git init` / `git clone` 只在专门的项目文件夹里做。
3. **`.git` 隐藏目录是仓库的命根子**：不要删、不要手动改里面任何文件。
4. **大文件别进 Git**：视频、数据集、安装包等几十 MB 以上的文件会让仓库膨胀、clone 极慢。用网盘/对象存储存放，Git 只存代码和文档。
5. **换行符问题只犯一次**：如果 `git status` 显示一堆没动过的文件"被修改"，九成是 `core.autocrlf` 没按 01 章设置。
6. **在两台设备上同时挂着未推送的改动是冲突温床**：收工 push 是对明天的自己负责。
7. **commit 之前 `git status` 一眼**：确认提交进去的就是你想提交的，没有混入临时文件。

## 结语

走到这里，你已经拥有：

- 两台设备各自可用的 Git 环境和独立 SSH 密钥
- 一个 GitHub 远程仓库作为权威中转站
- 一条简单可靠的日常纪律：**开工 pull → 写代码 → add / commit → 收工 push**
- 处理冲突、撤销失误、使用分支的进阶能力

这套配置可以原样复用到你的下一个项目：只需在 GitHub 新建仓库，然后 `git clone` 到两台设备即可。
